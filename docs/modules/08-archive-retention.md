# Модуль 8 — Архив originals и TTL хранения

**Статус:** in_progress  
**Зависимости:** [02-batch-watcher.md](02-batch-watcher.md), [04-api-web.md](04-api-web.md), [07-ui-ux-bild.md](07-ui-ux-bild.md)

## Цель

Снизить риск переполнения VPS-диска, сохранив "страховочное окно" для повторного скачивания пакетов после удаления из `incoming`.

## Согласованные правила

1. После удаления пакета из `incoming` файлы в `originals` остаются временно (по TTL).
2. TTL отсчитывается от момента, когда пакет фактически исчез из `incoming`:
   - после действий в кабинете (`Скачать все` / `Скачать выбранное`),
   - либо после ручного удаления в FileZilla.
3. Вкладка `Пакеты` показывает только актуальные пакеты из `incoming`.
4. Вкладка `Архив` показывает пакеты, вышедшие из `incoming`, но ещё живые по TTL.
5. По истечении TTL пакет удаляется из `originals` автоматически.

## Настройки (UI/конфиг)

- TTL (выпадающий список):
  - `1ч, 2ч, 3ч, 4ч, 5ч, 6ч, 8ч, 12ч, 24ч, 36ч`
  - default: `3ч`
- Лимит архива в ГБ (числовое поле в `Настройках`).
- Кнопка `Очистить архив` (ручная очистка архива).

## Индикатор заполнения

Во вкладке `Архив`:

- показывать занятый объём `originals` в ГБ,
- отображать процент от установленного лимита:
  - `used_gb / limit_gb` и `%`.

## План реализации

1. Backend-модель состояния архива:
   - зафиксировать timestamp "removed_from_incoming_at" для пакета.
2. Фоновая очистка:
   - удалять из `originals` всё, что старше выбранного TTL;
   - удалить пустые каталоги после удаления файлов.
3. API:
   - чтение/запись настроек TTL и лимита;
   - ручной endpoint `Очистить архив`;
   - endpoint списка архивных пакетов.
4. Frontend:
   - добавить вкладку `Архив`;
   - добавить настройки TTL/лимита;
   - добавить индикатор заполнения и кнопку очистки.

## Что уже внедрено в коде

1. **База и состояние:**
   - в `batches` добавлены поля `removed_from_incoming_at` и `archive_expires_at`;
   - watcher/API проставляют метку "ушёл из incoming" и TTL-дедлайн.
2. **Автоочистка:**
   - watcher и API-чтение архива запускают cleanup истёкших пакетов;
   - очистка удаляет файлы из `originals` и переводит пакет в `archived_deleted`.
3. **API архива:**
   - `GET/POST /api/archive/settings` (TTL + лимит ГБ),
   - `GET /api/archive/usage` (занято/лимит/%),
   - `GET /api/archive/batches`,
   - `GET /api/archive/batches/{batch_id}/download`,
   - `POST /api/archive/clear`.
4. **UI кабинета:**
   - добавлена вкладка `Архив` со списком архивных пакетов и кнопкой повторного скачивания;
   - в `Настройках` добавлены: TTL select, лимит ГБ, `Сохранить архив`, `Очистить архив`;
   - отображается индикатор заполнения архива (`used/limit`, `%`).

## Риски и ограничения

- Нужна аккуратная синхронизация состояния для ручного удаления через FTP (FileZilla).
- Нельзя чистить `incoming` этим модулем — только `originals`.
- Я.Диск не является частью TTL-очистки (зеркало сохраняется независимо).
